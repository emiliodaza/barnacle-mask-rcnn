# Scientist review workflow

The browser demo uses actual model proposals generated by the Python pipeline.
It does not run Mask R-CNN inside the browser. No external JavaScript library,
API key, account, or cloud service is required.

1. Serve the repository root: `python -m http.server 8000 --bind 127.0.0.1`.
2. Open `http://127.0.0.1:8000/demo/`. Choose the official unlabeled photograph or either held-out example.
3. Check the gold polygon follows the inner frame. Model proposals are teal. Use **Next** to inspect smaller tiles; it does not mark them as verified.
4. Click an extra proposal in **Remove extra** mode. **Show removed proposals** reveals dashed outlines that can be clicked to restore them.
5. In **Mark missed** mode, click the center of a missed barnacle; click its manual marker again to remove it. Added points affect the count but are not segmentation labels.
6. Use **Undo**, **Fit frame**, Pan mode, and mouse-wheel zoom as needed. Changing the score threshold is exploratory; it does not update the reported evaluation results.
7. Export accepted points as CSV and the review/audit as JSON. Coordinates refer to the original-resolution photograph. The JSON includes model provenance, selected region, threshold, edits, and a provisional count. Exports deliberately remain `review_complete: false`: the prototype has no independent verification of completed human review.

Corrections persist in this browser, scoped to the original image hash, proposal records, region, and checkpoint. Undo
history lasts for the current session. Changes to thresholds or frame regions can
hide prior corrections; these remain in the audit rather than silently vanishing.
Nothing is sent to a server. Browser storage can be cleared, so export important
work. Session event timestamps do not establish a scientifically measured time
saving.

## Your own photograph

1. Expand **Use your own photograph**, load a photo, and click the four inner corners in perimeter order. The frame must be a convex quadrilateral.
2. Export the frame region JSON. Save the original photo and JSON locally.
3. Run inference from the repository root:

   ```bash
   python -m src.predict --image path/to/photo.png \
     --region path/to/frame-region.json \
     --checkpoint outputs/final_raw.pth \
     --score-threshold 0.25 --output results/my-proposals.json
   ```

4. Keep the same photo loaded and load `my-proposals.json`. Review at score 0.5 initially; lowering to 0.25 exposes more proposals. Coordinate dimensions must match the photo exactly; original-file hashes are checked when available.

Existing proposals are not recomputed when the frame is changed. To expand beyond
the original inference region, export the new frame and rerun Python inference.
The prototype assumes the input photo has comparable pixel scale to training;
other cameras may need a scale-normalization step. Human points and proposal
edits require careful inspection and are not themselves ground truth.

## Follow-up experiment

Give scientists a small set of newly annotated regions. Randomize manual-only
versus proposal-assisted counting. Measure final verified count error, missed and
extra instances, and task time. Compare results before claiming the interface
speeds up counting. Do not substitute model precision/recall for this usability
experiment.
